Report No.005 · Agent Harness

DeepSeek Harness 解析：
模型 + Harness = Agent

2026 年 8 月，DeepSeek 开源了 DeepSeek Harness（命令名 dsh）。它不是新模型，而是一套「把模型变成编程 Agent」的外壳：工具、会话、界面、甚至 Agent 的行为方式，全都做成可以热插拔的插件。这一篇不读代码，而是汇总官方 README 和几篇公开解析，把它和研究所之前拆过的项目放在一起对照。

01取样：它是什么，为什么值得看

先回顾研究所第二篇 Harness² 里的定义：harness 是模型外面让它能干活的一整套东西，包括提示词、工具、记忆、技能、权限。多篇解析文章引用了 DeepSeek 的一句话：Model + Harness = Agent。模型负责想，其余全归 harness 管。

DeepSeek Harness 就是 DeepSeek 官方给出的这套「其余部分」：

样本卡
发布2026 年 8 月 13 日前后以开发者预览版开源（TechNode 8 月 14 日报道）
状态README 用大写警告：THERE WILL BE COMPATIBILITY-BREAKING CHANGES
技术底座Cordis，自称「时空可组合性的元框架」，Node.js / TypeScript，MIT 许可
启动npx @deepseek-ai/dsh web，在 127.0.0.1:3080 打开本地网页界面；10 月初又推出了 macOS 和 Windows 桌面版
默认模型DeepSeek 自家模型，也能在设置里加 OpenAI、Anthropic 或任意 OpenAI 兼容接口

它值得看，是因为这是模型厂商亲自下场做 harness：DeepSeek 自己公布的跑分，就是在这个 harness 的某个模式下测出来的。这让「harness 对成绩影响多大」这个问题，第一次有了官方的参照物。

02测绘：先看清全貌

一切皆插件

几乎所有解析都在强调同一点：模型适配器、工具注册表、会话、界面，连 Agent 循环本身，都是插件，可以在不改源码的情况下替换。GitHub 上带 dsh-plugin 话题的仓库就是社区插件，比如给纯文本模型加看图能力的 ModLens。

这些插件运行在 Cordis 之上。Cordis 的配套论文题为《A Programming Paradigm for Spatiotemporal Composability》（时空可组合性的编程范式）。官方资料对它说得很少，结合 Harness 的表现可以这样理解：「空间」指插件之间怎么组合，「时间」指插件在运行中被装上、换掉、卸下时，它带来的副作用怎么被干净地清理。后面要讲的 Creator 模式能在对话中途改插件，靠的就是这一点。

03解剖：几个关键设计

四种预设：换预设就是换 harness

据 OrcaRouter 的解析，dsh 内置四种预设，能力从少到多大致如下：

预设包含什么适合
Minimal只有常驻的 bash 和一个字符串替换编辑器（str_replace_editor）复现跑分
Standard（默认）完整编程 Agent：文件编辑、Shell、文件与网页搜索、技能、规划、目标、子代理、工作流日常开发
Code（PTC）Standard 加 Code Mode：模型写 TypeScript 小程序，一次串起多个工具调用多步批量操作
CreatorStandard 加运行时检查、内存里的插件实验和预设编写；Agent 能在对话中途安装、替换、销毁插件改造 harness 本身

这里有一个很值得注意的细节。DeepSeek V4 Flash 的 API 文档写着，它在 Terminal-Bench 2.1 上的 82.7 分是在 「DeepSeek Harness minimal mode」下跑出来的。也就是说，跑分用的是工具最少的那一档。解析文章也提醒：换预设换的是整个 harness，不只是模型；不同预设之间的成绩，不能直接当成模型能力的比较。

和 Harness² 对照

Harness² 证明了「同一个模型，换个 harness 成绩能差十几分」。dsh 把 Minimal 预设公开出来当跑分的参照环境，等于承认了这一点，也让别人能在同样条件下复现。这是一个好习惯：公布跑分时，连同 harness 一起公布。

Code Mode：又一个「让模型写代码调工具」

PTC 预设里的 Code Mode，思路和 OpenCode 的 CodeMode 一样，都源自 Cloudflare 的 Code Mode：与其让模型一次调一个工具、每次都把结果塞回上下文，不如让它写一段程序，把多个工具调用串起来，只返回最终需要的东西。

区别在于实现：OpenCode 自己写了一个只支持部分 JavaScript 的解释器，从根上限制能做的事；dsh 用的是 TypeScript 程序（具体沙箱方式本文没有核实）。解析文章特别提醒，这种模式可能放大副作用和工具调用次数：一段循环就可能连续改几十个文件。

会话是只追加的日志，可以重放、可以分叉

据解析，每次运行都会写一份只追加的会话日志：zstd 压缩的 JSONL 文件，每条事件带类型、序号、时间和数据。网页里的轨迹视图能查看每次模型回复、工具调用、耗时和 token 用量，还支持恢复、搜索、重放、分叉。

分叉特别实用：改一句指令，从同一个位置重新跑一遍，再和原来的结果对比。这其实就是 Harness² 里「在同一任务上探测不同改法」的手动版。

Creator 模式：Agent 改装自己

Creator 预设允许 Agent 在对话中途安装、替换、销毁插件。结合「Agent 循环本身也是插件」，理论上 Agent 可以在运行中改写自己的工作方式。这是 Cordis「运行时可组合」最激进的用法，也是风险最大的用法：建议只在隔离环境里尝试。

其他值得一提的

  • 子代理可以是别家的 Agent。据解析，dsh 能把 Claude Code 和 Codex 当作子代理的提供方来调用。
  • 上下文开销不小。有人实测，一个只要求回复「PONG」的任务，第一次请求就用了约 13,467 个输入 token，来自默认提示词、工具定义和注入的规则。这正好呼应了 REA 那篇里「工具说明本身就是 token 成本」。
  • 预览版的毛刺。DataCamp 的作者遇到过 Agent 无故中途停下、需要手动输入「继续」，并认为插件的安装配置偏难、文档偏少。

05结论

ONE-LINER

DeepSeek Harness 是模型厂商亲手做的「模型之外的一切」：一切皆插件，四种预设对应四种 harness，会话可重放可分叉。它还不是打磨好的产品，但它把「跑分到底在什么 harness 下测的」这件事摆上了台面。

适合谁

  • 主要用 DeepSeek 模型、想要一个官方配套 Agent 环境的人
  • 想复现 DeepSeek 公布的跑分、或者研究 harness 对成绩影响的人
  • 喜欢折腾插件、愿意帮一个预览版项目「补完」的开发者

什么时候不该用

  • 要稳定生产环境：预览版明确会有不兼容的改动
  • 想要开箱即用：Claude Code、Codex 目前更成熟
  • 不熟悉风险的人：Code Mode 和 Creator 模式权限很大，最好先在隔离环境试

放进研究所的系列里看

  • Claude Code：闭源的引擎，开放的扩展接口
  • OpenCode：开源的引擎，一切皆插件，自研 CodeMode 解释器
  • Harness²：证明 harness 能大幅影响成绩，并尝试自动改进它
  • REA：挂在 Agent 身上的超大工具箱，把 token 当成本来算
  • DeepSeek Harness：模型厂商自己的 harness，把跑分环境公开成一个预设

猪猪的三条收获

  1. 比较模型之前，先对齐 harness。同一个模型换个预设成绩就可能不同；看跑分时，要问一句「在什么环境下测的」。
  2. 只追加的日志是 Agent 的「黑匣子」。能重放、能分叉，调试和对比实验都会轻松很多，自己做 Agent 时值得一开始就设计进去。
  3. 二手资料要交叉核对。这篇最大的工作量不在写，而在把几份说法不一的来源对齐。
