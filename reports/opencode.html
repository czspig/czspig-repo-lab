Report No.003 · AI Agent

OpenCode 深度解析：
把 Agent 做成一台服务器

OpenCode 是开源的 AI 编程 Agent，可以看作 Claude Code 的开源同类：终端里对话，能读写代码、跑命令。不同的是它的引擎完全开源，能接近 30 家模型服务，也能接你电脑上的 Ollama。这一篇拆它的架构、主循环和权限系统，再用本地小模型真的让它干一次活。

01取样：它是什么，为什么值得拆

研究所前两篇正好留了一个空：Claude Code 的引擎看不到源码，Harness² 默认拿来干活的执行器又恰好是 OpenCode。拆完它，三篇就连成了「闭源产品 → 开源同类 → 改进它的框架」。

样本卡
规模8582 个文件的 Bun + TypeScript 单仓库，34 个包，packages/*/src 下约 57 万行，核心包 packages/core 约 6.9 万行
技术栈Bun 运行时、Effect 函数式框架、SQLite（Drizzle）、Vercel AI SDK
入口终端 TUI、桌面 App（Beta）、网页、VS Code 插件，以及给 Zed 等编辑器用的 ACP 协议
模型约 30 家服务商插件：OpenAI、Bedrock、Vertex、OpenRouter、GitHub Copilot……以及本地的 Ollama、LM Studio、vLLM

和 Claude Code 最直观的区别：模型随便换，代码全公开。但读完源码会发现，真正有意思的是下面几个架构决定。

02测绘：先看清全貌

界面只是客户端

仓库根目录的 AGENTS.md 写了一条依赖铁律：

AGENTS.md原文节选

Keep runtime dependencies directed from Schema to Core and Protocol, then from Core and
Protocol to Server. Client runtime code may depend on Schema and Protocol but never Core
or Server; `sdk` composes Client, Core, and Server.

翻译过来：Agent 的引擎（Core）跑在一个本地后台服务（Server）里，终端界面、桌面 App、网页都只是连上去的客户端，只认识协议（Protocol），碰不到引擎内部。开发文档里的 opencode service status、opencode service get password 就是在查这个后台服务的地址和本地凭据。

好处很实际：会话存在服务和数据库里，不依附于某个窗口；终端和桌面 App 可以连同一个服务；还能通过隧道从远程连进来。服务启动时会把自己的地址、进程号和访问密码写进一个本地文件，客户端读这个文件来连接。

03解剖：读到关键代码

主循环：一步一步往前推

Agent 的心脏在 session/runner/llm.ts 的 runStep。每一「步」是一次完整的模型请求，加上这次请求里所有的工具调用。每步开始前都要过几道检查：

  1. 先看要不要压缩。上下文快满了就先压缩历史，压缩完换一个新的回复 ID 重来。
  2. 再看步数用完没有。到了 Agent 设定的步数上限，就在消息末尾塞一段「已达最大步数，只许用文字总结」的提示，并把 toolChoice 设成 none。
  3. 发请求、执行工具。交给 step.ts 的 attempt，它还会趁模型思考时顺手拍一张文件快照，留着撤销用。
  4. 按结果分流。attempt 返回六种结局之一，主循环逐个处理。
结局主循环怎么处理
Completed正常结束；如果模型还调用了工具，就进入下一步
Retry按重试策略等待后重发（比如服务商限流）
Continue流式输出半路断了，补一条「请接着说」再来
OutputLimit回答被输出长度截断，让模型接着写；连续三次被截断就放弃
Compacted请求时发现上下文溢出，压缩后重来，但只给一次机会
RecoverFull连接在模型开始输出之前就断了，整个请求原样重发

有个细节很能说明这份代码的功力：

packages/core/src/session/runner/llm.ts节选

// Keep tool definitions on the final Step to preserve the provider's cached prefix.
toolChoice: stepLimitReached ? "none" : undefined,

最后一步明明不许用工具，却不删工具定义，只把 toolChoice 设成 none。原因是删掉会改变请求的前缀，服务商那边的提示词缓存就失效了，这一步会更慢也更贵。

权限：后写的规则说了算

权限系统只有一个核心函数，十几行：

packages/core/src/permission.ts节选

export function evaluate(action, resource, ...rulesets) {
  return rulesets.flat()
    .findLast((rule) => Wildcard.match(action, rule.action) && Wildcard.match(resource, rule.resource))
    ?? { action, resource: "*", effect: "ask" }
}

三条规矩：规则按顺序叠起来，最后一条匹配的生效；一条都不匹配就问用户；如果连对应的 Agent 都找不到，就用一条「全部拒绝」兜底。用户点过「总是允许」的，会按项目存进数据库，下次自动放行。

内置的 Explore 子代理把「后者优先」用得很漂亮：

packages/core/src/plugin/agent.ts · Explore节选

{ action: "*",    resource: "*",             effect: "deny" },   // 先全部禁止
{ action: "read", resource: "*",             effect: "allow" },  // 读文件放开
{ action: "read", resource: "*.env",         effect: "ask" },    // 但 .env 要问
{ action: "read", resource: "*.env.*",       effect: "ask" },
{ action: "read", resource: "*.env.example", effect: "allow" },  // 示例文件又放开

从宽到窄一层层覆盖，读起来就像一份说明书。对比 Claude Code 用 Hook 脚本拦截，OpenCode 把大部分权限做成了纯数据，规则本身就能审查。

一切皆插件

OpenCode 自己的东西大多也是用插件接口写的：

  • 模型服务商：plugin/provider/ 下每家一个文件。ollama.ts 会请求本机 127.0.0.1:11434 的 /api/tags 自动发现模型，再读每个模型的能力列表。只有声明了 tools 能力的模型才会被当成能调工具的 Agent 模型。
  • 内置工具：tool/plugin/ 里的 read、edit、shell 等，和第三方插件、MCP 工具注册方式完全一样。同名工具后注册的覆盖先注册的，撤销注册后原来的又会露出来。
  • 内置 Agent：Build（默认）、Plan、General、Explore，以及隐藏的 Title、Summary、Compaction，都在 plugin/agent.ts 里用同一套 transform 接口定义。

第三方插件能改的范围很大：agent、command、mcp、model、provider、skill、tool 等十一个领域都有 transform 钩子，另外还能在发请求前改上下文、自定义重试策略。

CodeMode：让模型写代码来调工具

这是最「研究性」的设计。工具默认会被放进 CodeMode：模型不是一次调一个工具，而是写一小段代码，在里面调用多个工具、处理结果，最后只把需要的东西返回。这个想法最早来自 Cloudflare，好处是多步操作能在一次往返里完成，中间结果也不用塞进上下文。

OpenCode 没有去沙箱真正的 JavaScript，而是自己写了一个解释器（packages/codemode），只实现一部分 JS 语法：

  • 没有 process、文件系统、网络、import，也没有定时器；想碰外部世界只能通过宿主给的工具
  • 程序结束时还没完成的工具调用会被中断
  • 不支持的语法直接返回带位置的诊断信息

「只实现需要的部分」比「把危险的部分关掉」安全得多：没实现的功能，自然不存在被绕过的可能。

04复现：把权限求值搬出来跑一遍

先说明

本来计划在本机用 Ollama 的 granite4.1:3b 小模型真跑一次 OpenCode，但 Windows 版可执行文件有 219 MB，在本机网络下两次都没下完，于是改成一个更小、但同样基于真实代码的实验：把权限系统的两个核心函数照着源码移植成 Python，用 Explore 子代理的真实规则去跑。

移植的对象是 permission.ts 里的 evaluate（倒序找第一条匹配，找不到就 ask）和 util/wildcard.ts 里的 match：

packages/core/src/util/wildcard.ts原文

export function match(input: string, pattern: string) {
  const normalized = input.replaceAll("\\", "/")
  let escaped = pattern
    .replaceAll("\\", "/")
    .replace(/[.+^${}()|[\]\\]/g, "\\$&")
    .replace(/\*/g, ".*")
    .replace(/\?/g, ".")

  if (escaped.endsWith(" .*")) escaped = escaped.slice(0, -3) + "( .*)?"

  return new RegExp("^" + escaped + "$", process.platform === "win32" ? "si" : "s").test(normalized)
}

perm.py移植后的核心

def match(text, pattern, windows=True):
    text = text.replace("\\", "/")
    p = "".join(".*" if c == "*" else "." if c == "?" else c if c == " " else re.escape(c)
                for c in pattern.replace("\\", "/"))
    if p.endswith(" .*"):
        p = p[:-3] + "( .*)?"
    return re.fullmatch(p, text, re.S | (re.I if windows else 0)) is not None


def evaluate(action, resource, rules):
    hit = [r for r in rules if match(action, r[0]) and match(resource, r[1])]
    return hit[-1][2] if hit else "ask"      # findLast，找不到就 ask

结果

请求结果为什么
read src/app.pyallow只命中 read *
read .envask后面的 read *.env 覆盖了前面的 allow
read config\prod.envask反斜杠先被换成 /，而且 * 会跨目录匹配
read .env.localask命中 *.env.*
read .env.exampleallow最后一条把示例文件重新放开
read SECRETS.ENVask（Windows）Windows 上不区分大小写
edit src/app.pydeny只命中第一条 * * deny：Explore 只读
subagent generaldeny同上，不许再派子代理
空规则集下 edit calc.pyask没有任何匹配，默认询问

还有一个小机关：模式以「空格 + *」结尾时，后面那段变成可选。所以 git * 既匹配 git status，也匹配光秃秃的 git，但不会匹配 gitk。实测结果：True 和 False。

发现

同一套规则，在不同系统上结论可能不同。SECRETS.ENV 在 Windows 上是 ask；换到 Linux，匹配区分大小写，*.env 不命中，它会落回 read * 变成 allow。大小写混用的敏感文件名，在 Linux 上要自己补一条规则。

对照上一篇

Harness² 在 Windows 上栽在了反斜杠路径上，所有改动被静默丢弃。OpenCode 的通配函数第一行就是 replaceAll("\\", "/")，最后再按平台决定是否忽略大小写。跨平台的坑，它提前填好了。

想自己跑一次完整的 Agent？

按官方 README 安装后，用本地 Ollama 模型就能离线试，不花钱。下面的 granite4.1:3b 是我电脑上已有、并且声明了 tools 能力的模型：以下命令本文没有实际运行：

npm i -g @opencode/cli@latest
opencode run -m ollama/granite4.1:3b "修复 calc.py 里 average 的 bug"          # 非交互：需要授权的操作会被自动拒绝
opencode run -m ollama/granite4.1:3b --auto "修复 calc.py 里 average 的 bug"   # --auto：未被明确禁止的操作自动放行

按源码 run/noninteractive.ts 的逻辑，不加 --auto 时权限请求会被自动拒绝，模型会收到一句「这次非交互运行没法问用户，请求已被拒绝，请不用这个操作继续」，然后接着想别的办法。

05结论

ONE-LINER

OpenCode 把编程 Agent 做成了一台本地服务器：界面只是客户端，模型、工具、Agent 全靠插件装上去，权限是一张「后写的说了算」的规则表。它不只是 Claude Code 的开源平替，而是一套可以被拆开、改造、嵌进别的系统里的 Agent 底座。

适合谁

  • 想换模型、用本地模型或多家服务商比价的人
  • 要把编程 Agent 嵌进自己产品或研究流程的人，比如 Harness² 就把它当执行器
  • 想读一份生产级 Agent 源码的人：主循环、压缩、重试、权限都写得很讲究

什么时候不该用

  • 只想开箱即用、不想配置模型的人：Claude Code 这类一体化产品更省心
  • 想快速读懂整个项目：57 万行、34 个包，还大量使用 Effect，上手门槛不低
  • 网络条件差又要用本地模型：光可执行文件就两百多兆

猪猪的三条收获

  1. 把引擎和界面拆开。引擎做成服务，界面只认协议，多端共享会话就是顺手的事。自己的项目哪怕只有一个界面，也值得把核心逻辑写成不依赖界面的服务。
  2. 权限做成数据，而不是代码。一张从宽到窄的规则表，比散落在各处的 if 判断好审查得多；但要记得规则匹配本身也有平台差异。
  3. 省钱的细节藏在边角里。最后一步保留工具定义只为了命中提示词缓存，这种决定只有真正盯过账单的团队才会写。
